# Тестовое задание backend-разработчик
## “API ДЛЯ УЧЕТА ТРАНЗАКЦИЙ И ПОКУПКИ БАЛЛОВ”
## Задача
Разработать REST API для учета пользовательских финансовых транзакций и покупки баллов. 
Представим, что у нас есть система с учетом денежных средств пользователя, в которой пользователь может тратить свои средства (funds) на баллы (points). Средства хранятся в единой валюте USD. Схему данных нужно подобрать на усмотрение кандидата: необходимую и достаточную для имплементации следующей функциональности.

### Требования к функциональности:
1. Аутентификация пользователей:
   - [ ] Механизм входа (token-based аутентификация).
     - [ ] Получение access-token, refresh-token
     - [ ] Логаут (ревоук токена)
     - [ ] Регистрацию можно опустить в реализации.
   - [ ] Доступ к API только для аутентифицированных пользователей.
2. Финансовые транзакции:
   - [ ] Создание транзакций:
     - [ ] Начисление средств (представим, упрощенно, что пользователь кладет деньги на баланс).
     - [ ] Сервисное списание средств с переводом на системный счет (фоновая процедура в Python-треде, которая раз в сутки списывает со счета каждого пользователя по 1 USD).
     - [ ] Покупка баллов.
     - [ ] Перевод средств (не баллов) между пользователями.
   - [ ] Возможность получения списка транзакций + фильтрация/сортировка по типу, дате, получателю + паджинация
3. Получение баланса:
- [ ] Баланс средств пользователя.
- [ ] Баланс баллов.

### Требования к реализации:
- [x] Язык программирования: Python 3.10
- [x] Фреймворк: FastAPI
- [ ] База данных: SQLite
- [ ] Несколько тестов самых важных на взгляд кандидата частей проекта
- [ ] Докеризация, конфигурируемость
- [ ] Логирование операций способом, на выбор кандидата
- [ ] Использовать как можно меньше внешних зависимостей
Общие требования:
- [ ] Структуру проекта, модели и логику должен продумать сам разработчик. Допустим необходимый и достаточный набор полей.
- [ ] README с краткой инструкцией по запуску и описанием эндпоинтов API.
